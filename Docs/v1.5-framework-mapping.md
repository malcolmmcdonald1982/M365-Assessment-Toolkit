## UX Design Decision — Framework Selector

### The Problem
Showing all 8 frameworks to a UK SMB who only needs Cyber Essentials is overwhelming
and dilutes the report. Client reports must only show what is relevant to that client.

### The Rule
- **Consultant view (tool UI)** — always show all frameworks. Consultant needs full visibility.
- **Client report (Word output)** — only show frameworks selected for that engagement.

### Implementation

**1. Add `active_frameworks` to session/engagement config**
```python
# Default — all active on first load
active_frameworks = [
    "cis", "nist", "iso27001", "cyber_essentials",
    "soc2", "ncsc_caf", "essential_eight", "nis2"
]
```
Saved in session file so selection persists across the engagement.

**2. Framework selector in sidebar — Client Details section**
Add a multi-select checklist under the existing client name/consultant fields:

```
Compliance Frameworks in Scope
☑ CIS M365 v7.0.0
☑ Cyber Essentials v3.3
☐ NIST CSF 2.0
☐ ISO 27001:2022
☐ SOC 2 CC6/CC7
☐ NCSC CAF v4.0
☐ Australian Essential Eight
☐ EU NIS2 Article 21
```

Set once at engagement start. Everything else in the tool respects this selection.

**3. What respects active_frameworks**
- Finding card badges — only show selected framework chips
- Finding filter dropdown — only lists selected frameworks
- Simulator gap counters — only show selected frameworks in banner
- Word report findings table — only selected framework columns appear
- Word report compliance summary page — only selected frameworks
- Comparison report — progress metrics only for selected frameworks
- Report footer — only cites selected frameworks

**4. Report generation override**
At report generation time, allow the consultant to override the sidebar selection
for that specific report only (e.g. generate a CE report and a full report separately).

### Example Outcomes

**UK SMB — Cyber Essentials only selected:**
- Finding cards show one badge: `CE · UAC`
- Simulator shows: `CE GAPS: 12 → 4`
- Word report has one framework column, clean and focused
- Client feels the report was written specifically for them

**Enterprise — ISO 27001 + SOC 2 selected:**
- Finding cards show two badges: `ISO A.8.5` and `SOC2 CC6.5`
- Simulator shows two gap counters
- Word report has two framework columns plus compliance summary page

**Consultant internal review — all frameworks active:**
- Full view — consultant can spot NIS2 exposure even if client isn't aware they're in scope
- Useful for upsell conversations ("you're also exposed under NIS2...")

### Priority
Build the selector before building the badges — it defines what gets rendered everywhere.

## UX Design Decision — Simulator What-If Export (Framework-Aware)

### Background
The simulator already has an Export What-If Report in v1.4. It currently covers:
- Attack chain status (broken / still active)
- Simulated score vs current score
- Findings toggled as fixed
- Risk narrative

At v1.5 this export gains a full compliance what-if layer, making it a planning and
project brief tool — not just a risk report.

### What the Enhanced Export Contains

**Section 1 — Summary header**
```
WHAT-IF REPORT — [date]
Client: [name]    Consultant: [name]
Frameworks in scope: [only active_frameworks]
```

**Section 2 — Score comparison**
```
CURRENT STATE
  Attack Path Score:     36 / 100
  MS Secure Score:       48%
  [Framework] Gaps:      12

SIMULATED STATE (N findings remediated)
  Attack Path Score:     71 / 100    (+35)
  MS Projected Score:    67%         (+19%)
  [Framework] Gaps:      4           (-8)
```

**Section 3 — Per-framework compliance coverage (pillar-level where applicable)**
For Cyber Essentials and Essential Eight (named pillars):
```
CYBER ESSENTIALS — SIMULATED COVERAGE
  Firewalls:             ✅ Met
  Secure Configuration:  ✅ Met
  User Access Control:   ⚠ 3 gaps remain
  Malware Protection:    ✅ Met
  Patch Management:      ⚠ 1 gap remains
```
For ISO, NIST, SOC 2, NIS2 (control-level):
```
ISO 27001:2022 — SIMULATED COVERAGE
  Open controls: 4 remaining (down from 11)
```

**Section 4 — Findings simulated as fixed**
Each finding shows which framework gaps it closes:
```
FINDINGS SIMULATED AS FIXED
  ID-002  Admins Without MFA      → CE: UAC  |  CIS: 5.2.2.1  |  NIS2: Art.21(k)
  CA-003  No MFA for All Users    → CE: UAC  |  ISO: A.8.5    |  SOC2: CC6.5
  EXO-004 DMARC Not Configured    → CE: SC   |  CIS: 2.1.10   |  NIS2: Art.21(i)
```

**Section 5 — Findings still open**
```
FINDINGS STILL OPEN
  MDM-003  No Windows Update Ring    CE: PM gap remains
  MDM-004  BitLocker Not Enforced    CE: SC gap remains
  SEC-006  No Microsoft Sentinel     (no CE mapping)
```

**Section 6 — Recommended next steps**
Auto-generated summary based on remaining gaps:
```
RECOMMENDED NEXT STEPS
  To achieve full Cyber Essentials compliance, fix these 4 remaining findings:
  - MDM-003 — No Windows Update Ring (Patch Management)
  - MDM-004 — BitLocker Not Enforced (Secure Configuration)
  ...

  Fixing these findings will also close:
  - 3 additional NIS2 Article 21 obligations
  - 2 additional ISO 27001 Annex A controls
```

### Why This Matters

The What-If export becomes the client's **remediation project brief**:

| Who uses it | How |
|---|---|
| Client IT team | Exact list of what to fix and why — compliance justification included |
| Client board | Executive summary showing compliance target achievable and how far away |
| Consultant | Scopes the next engagement — here's what phase 2 covers |
| Auditor | Evidence that a structured remediation plan exists with compliance rationale |

### Workflow This Enables
1. Run assessment → current gaps identified
2. Open simulator → toggle findings until target framework gaps hit zero
3. Export What-If report → client IT team has remediation roadmap
4. IT team remediates → run next assessment
5. Comparison report → proves compliance progress to auditors/board

### Output Format
- Word (.docx) — consistent with all other reports, client-branded
- Only includes active_frameworks — CE-only client sees CE content only
- Respects framework selector — same rule as all other reports
